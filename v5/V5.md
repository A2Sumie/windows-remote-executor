# WRE v5 — pure-Python Windows Remote Executor protocol

V5 is the audit-hardened successor of v4 (see
`.agent/reports/2026-08-18-wre-v4-audit.md`). Same architecture: a Python
embeddable interpreter on the Windows host, driven by one JSON line over SSH
stdin/stdout. **PowerShell, cmd.exe argv composition, and arbitrary
process.run / spawn / exec actions remain gone.** The only Windows
process-launching primitive is the scheduled-task lifecycle via TaskScheduler
COM.

**Wire compatibility:** v5 keeps the v4 request/response shape and the same
remote command path. `protocolVersion: 5` is a capability marker
(`host.capabilities` also reports `"build": "v5"`).

## Trust model — read this first

**Holding the access token == having SYSTEM on the host.** Not because the
RPC process is elevated — it is not — but because the token holder can:

1. `file.writeText` an arbitrary `C:/CodexRemote/wre/apply-tasks.json`
   (spec `tasks:[...]`, any command as SYSTEM) and trigger the SYSTEM
   apply-agent via `host.tasks.apply`; or
2. overwrite `C:/CodexRemote/wre/rpc.py` itself and wait ≤ 10 minutes for the
   SYSTEM `CodexRemote Sshd Repair Watch` task to execute it.

The wre tree has no integrity protection; the token IS the root boundary.
v5 narrows the *transport* and *mistake* surface, not the permission ceiling.
Protect the token accordingly (never commit it; see `.gitignore`).

The `file.*` write/delete actions carry a **protected-prefix guardrail**
(`C:/CodexRemote/wre`, `C:/ProgramData/ssh`, `C:/Windows`) that refuses the
operation unless the payload sets `"allowProtected": true`. This is a
fat-finger guardrail for operators and agents — NOT a security boundary; any
token holder can set the flag.

## Stability boundary

Remote command (controller-provided over SSH; see `v5/controller/client.py`):

```text
cmd.exe /d /s /c "C:/CodexRemote/wre/python/python.exe -I -X utf8 C:/CodexRemote/wre/rpc.py rpc-stdio"
```

- stdin: one UTF-8 JSON request line, terminated by `\n`.
- stdout: one UTF-8 JSON response line, terminated by `\n`.
- stderr: not part of the contract; debugging only.
- Request lines are capped at 16 MB (putBinary's 4 MB base64 fits comfortably).

`-I` isolates the interpreter (`PYTHONPATH`, `*.pth` ignored by default).
`-X utf8` forces UTF-8 IO. Payloads never travel in argv.

`deploy-wre.py --force-command` can additionally pin a
`ForceCommand pythonw.exe ... rpc.py rpc-stdio` line in `sshd_config`, but it
is **opt-in** (v4 wrote it by default): ForceCommand kills the SSH user's
sftp/scp/interactive sessions because rpc.py does not dispatch
`SSH_ORIGINAL_COMMAND`, and that breaks the deploy_sftp loop.

## Request

```json
{
  "id": "req-001",
  "action": "host.probe",
  "timeoutSeconds": 30,
  "accessToken": "plain policy token",
  "payload": { "categories": ["os", "sshd"] }
}
```

`timeoutSeconds` is **record-only** on the native side (kept for forward
compatibility): the native process does not interrupt itself. The controller
enforces the real deadline via its SSH transport timeout
(`timeoutSeconds + 30`).

## Response

```json
{
  "id": "req-001",
  "ok": true,
  "protocolVersion": 5,
  "errorClass": "",
  "stdoutText": "...",
  "stderrText": "",
  "stdoutEncoding": "utf-8",
  "stderrEncoding": "utf-8",
  "startedAt": "2026-08-18T06:00:00.000000+00:00",
  "endedAt": "2026-08-18T06:00:01.000000+00:00",
  "durationMs": 1000,
  "data": { },
  "evidence": ["host.probe"]
}
```

These are the exact fields the native emits — there is no `stdoutBase64` /
`stdoutBytes` (v4's doc listed fields the code never produced). Binary file
content travels inside `data.base64` for `file.readText`. `durationMs` is
present on every dispatched response; it is absent only for protocol-level
parse failures (malformed JSON / oversized line), which never reach dispatch.

`errorClass` is one of exactly:

| errorClass | Meaning |
|---|---|
| `protocol` | Unparseable/empty/oversized request line. |
| `auth` | Access-policy refusal (missing/corrupt/null-token policy, missing or wrong token). |
| `unsupported` | Unknown action name. |
| `request` | Bad payload (missing fields, invalid values, guardrail refusals). |
| `not-found` | Referenced file/directory does not exist. |
| `remote-exception` | Unhandled native exception (traceback tail in `stderrText`). |

## Access policy (FAIL-CLOSED)

Located next to `rpc.py` at `C:/CodexRemote/wre/access-policy.json`:

```json
{
  "expectedListenAddress": "100.119.106.8",
  "exposureMode": "private-only",
  "commandMode": "v5",
  "label": "PRIVATE-ONLY",
  "accessTokenSha256": "<sha256 of plain token>",
  "updatedAt": "..."
}
```

v5 enforcement rules (fixing v4's fail-open findings):

- **Missing or corrupt policy file → deny everything** except
  `host.capabilities` (errorClass `auth`, message says which).
- **`accessTokenSha256: null` → deny everything** except `host.capabilities`.
  There is no silent open mode.
- **Default-deny for actions:** every registered action requires the token;
  only `host.capabilities` is exempt. Future actions are automatically
  protected — there is no opt-in list to forget.
- `host.capabilities` stays open deliberately: a locked-out controller can
  still identify the bridge (`build: "v5"`, action list).

`host.policy` write semantics (self-service over RPC):

| payload | result |
|---|---|
| `{"token": "plain"}` | installs sha256(token) |
| no `token`, existing policy has a hash | **preserves** the existing hash (a bare host.policy can never erase an installed token) |
| `{"disableToken": true}` | explicitly writes `accessTokenSha256: null` |
| no `token`, no existing hash, no `disableToken` | refused (errorClass `request`) |

**Warning:** `disableToken: true` locks the bridge — afterwards every action
including `host.policy` is denied (`auth`). Recovery is out-of-band:
`deploy_sftp --access-token` (SFTP path, does not use RPC) or an on-host edit.

Policy writes are atomic (tmp file + `os.replace`).

## Actions (20)

### Host
| Action | Payload | Notes |
|---|---|---|
| `host.capabilities` | `{}` | Returns the registered action list + `build:"v5"`. Pure registry read; no COM. Token-exempt. |
| `host.probe` | `{ "categories": ["os","sshd","policy","tasks","python"] }` | Opt-in categories; default `["os","sshd","policy"]`. Policy category includes `policyStatus` (ok/missing/corrupt). |
| `host.guard` | `{ "expectedListenAddress":"100.x", "noDisable":true, "logPath":"..." }` | Read-only when `noDisable=true`. Authoritative exposure check. |
| `host.repair` | `{ "forceRewrite":false }` | Rewrites `sshd_config`, restarts `sshd` **only if the config changed or the service is not Running** (v4 restarted unconditionally and the 10-min watch killed long SSH sessions), ensures scheduled tasks + firewall rule. |
| `host.policy` | `{ "exposureMode":"private-only", "expectedListenAddress":"100.x", "label":"PRIVATE-ONLY", "token":"plain", "disableToken":false }` | See token semantics table above. |

### Scheduled tasks (TaskScheduler COM — no schtasks.exe)
| Action | Payload | Elevation |
|---|---|---|
| `host.tasks.list` | `{ "prefix":"CodexRemote", "taskNames":["..."] }` | Read-only. Works non-elevated. |
| `host.tasks.detail` | `{ "name":"..." }` | Read-only. |
| `host.task.create` | `{ "name":"...", "exe":"C:/...", "args":["/c","..."], "cwd":"...", "trigger":"manual\|logon\|startup\|boot\|interval", "delay_iso":"PT30S", "interval_minutes":10, "run_as_user":"SYSTEM\|\|DOMAIN\\USER", "run_level":0\|1, "enabled":true }` | Depends on host token filtering (see below). |
| `host.task.update` | Same shape as create. | Read-modify-write: fields absent from the spec keep existing definition values (triggers/principal/settings/untouched action fields). If the existing definition is unreadable, degrades to full rebuild and returns `partial: false`. |
| `host.task.run` | `{ "name":"..." }` | No — calling `Run()` on an existing task is permitted to admin-token holders without elevation. |
| `host.task.delete` | `{ "name":"..." }` | Yes (only SYSTEM/store owned). |
| `host.tasks.apply` | `{}` | Triggers the SYSTEM `CodexRemote WRE Apply` agent (must have been installed once, elevated). No elevation needed to trigger. |

Task names are validated: `\/:*?"<>|` and control characters rejected,
length ≤ 200. `args` are composed with `subprocess.list2cmdline` (real
Windows argv quoting; v4's `" ".join` broke args containing spaces/quotes).

### Files (stdlib pathlib / shutil)
| Action | Payload |
|---|---|
| `file.writeText` | `{ "path":"C:/...", "text":"...", "allowProtected":false }` |
| `file.readText` | `{ "path":"C:/...", "maxBytes":1048576 }` — maxBytes enforced from `stat` BEFORE reading. |
| `file.mkdir` | `{ "path":"C:/...", "allowProtected":false }` |
| `file.deleteTree` | `{ "path":"C:/...", "allowProtected":false }` |
| `file.copy` | `{ "source":"C:/...", "destination":"C:/...", "allowProtected":false }` — guard applies to the destination. |
| `file.putBinary` | `{ "path":"C:/...", "base64":"...", "allowProtected":false }` — small files only (≤ 4 MB). Use SFTP for big. |
| `file.list` | `{ "path":"C:/...", "pattern":"*.ps1", "recursive":false, "maxEntries":500 }` — bounded directory listing. |
| `file.search` | `{ "root":"C:/...", "nameGlob":"*.rs", "contentRegex":"...", "maxMatches":100, "maxFileBytes":1048576 }` — walk by name glob and/or first-match-per-file content regex. |

Protected prefixes for the write/delete-class actions (writeText, mkdir,
deleteTree, copy destination, putBinary): `C:/CodexRemote/wre`,
`C:/ProgramData/ssh`, `C:/Windows` (case-insensitive, `..`/`.`-normalized).
Refusal is errorClass `request`. Override per-call with
`"allowProtected": true` — guardrail, not a boundary (see Trust model).

## Elevation — the truth

`rpc.py` runs as **the SSH login user** (on X570 that is `sumie`, NOT
SYSTEM — verified 2026-08-18). v4-era documents claiming "rpc.py runs as
SYSTEM" were wrong.

SYSTEM is reachable through three explicit paths:

1. **`host.task.create` direct** — works when the host's token filtering lets
   the SSH-logon user call `RegisterTaskDefinition` with `run_as_user`=
   `SYSTEM`. Verified working on X570 from the unelevated SSH session (~180
   SYSTEM tasks created this way). Do NOT assume it on every host.
2. **`host.tasks.apply`** — triggers the `CodexRemote WRE Apply` scheduled
   task, which runs `rpc.py apply-tasks` as SYSTEM and (re)registers every
   task in `C:/CodexRemote/wre/apply-tasks.json`. Installed once by the
   elevated `deploy-wre.py`; the reliable cross-host SYSTEM path.
3. **Repair watch** — `CodexRemote Sshd Repair Watch` runs
   `rpc.py repair-sshd` as SYSTEM every 10 minutes (boot trigger + repetition).
   It executes the deployed wre tree, which is why tree integrity == SYSTEM.

The elevated `deploy-wre.py` run is the one-time bootstrap for paths 2 and 3,
not a per-call requirement.

## Audit log

Every dispatched request appends one JSONL line to
`C:/CodexRemote/logs/rpc-audit.log` (best-effort: write failures never block
the RPC; the log is written only on Windows hosts). Fields:
`ts`, `id`, `action`, `ok`, `errorClass`, `durationMs`.

Other host logs: `C:/CodexRemote/logs/sshd-repair.log`,
`C:/CodexRemote/logs/sshd-guard.log`, `C:/CodexRemote/logs/wre-apply.log`.

## Deployment

Two-stage (unchanged layout: `C:/CodexRemote/wre/`, remote command path
unchanged):

1. **Light deploy** (controller, no elevation):
   ```
   PYTHONPATH=. python3 -m v5.scripts.deploy_sftp <target> [--access-token <plain>]
   ```
   Determines the token hash from `--access-token`, else the target's v3
   policy, else the live `C:/CodexRemote/wre/access-policy.json`; **aborts
   with an explicit error when no token source yields a hash** (v5 never
   deploys a null-token policy). Stages the build tree + policy into a local
   TemporaryDirectory and uploads ONE tarball (v4 uploaded ~18 MB twice).
   Verify immediately:
   ```
   PYTHONPATH=. python3 -m v5.scripts.verify_v5_remote <target>
   ```

2. **One-time elevated deploy** (operator on the Windows host):
   ```
   C:\CodexRemote\wre\python\pythonw.exe C:\CodexRemote\wre\deploy-wre.py --target-name <name> --expected-listen <tailscale-ip> (--access-token <plain> | --keep-existing-policy)
   ```
   Exactly one of `--access-token` / `--keep-existing-policy` is required
   (there is no null-token default policy). Re-creates the sshd self-repair
   tasks, writes `apply-tasks.json`, installs the `CodexRemote WRE Apply`
   SYSTEM agent. `--force-command` is opt-in (see Stability boundary).
   `--tasks-only` re-registers tasks against an already-deployed tree.

## StreamServ launch flow

Pre-register ONCE during elevated deploy-wre (or any time via
`file.writeText` of an apply spec + `host.tasks.apply`):
```
host.task.create {
  "name": "CodexRemote StreamServ Start",
  "exe": "D:/StreamServ/start_streamserv_backend.cmd",
  "trigger": "manual",
  "run_as_user": "SYSTEM",
  "run_level": 1
}
```

Remotely trigger runtime:
```
host.task.run { "name": "CodexRemote StreamServ Start" }
```

Read logs:
```
file.readText { "path": "D:/StreamServ/logs/latest.log" }
```

No `process.run` / `process.spawn` / argv-from-controller anywhere.

## What was removed (vs v3)

- `process.run`, `process.capture`, `process.spawn` — replaced by TaskScheduler
  COM for resident launches.
- `script.run`, `script.capture` (PowerShell/cmd script bodies) — gone.
- `python.run` — gone.
- `wsl.*` actions — moved to a separate WSL control subsystem.
- `everything.search` — removed. Use `file.list` / `file.search`.
- `--allow-powershell`, `WIN_REMOTE_ALLOW_RAW_POWERSHELL` — gone.
- `argv-only` policy mode — gone.
- (v4→v5) the never-implemented `captureLimitBytes` request field — gone from
  the controller.

## Embeddable Python package

Built per release by `v5/scripts/make_bootstrap_package.py`. Layout:

```
wre-v5.0.0-windows-x64/
├── python/                    # frozen embeddable Python 3.12.10 + pywin32 308 + comtypes 1.4.8
│   ├── python.exe
│   ├── pythonw.exe
│   ├── python312._pth           # patched: `import site` + `Lib/site-packages`
│   ├── pywintypes312.dll        # flattened from pywin32_system32 post-install
│   ├── pythoncom312.dll         # flattened
│   └── Lib/site-packages/...
├── wre/                         # copied to C:\CodexRemote\wre\
│   ├── rpc.py
│   ├── actions/
│   ├── win32/
│   └── deploy-wre.py
├── deploy-wre.py
└── manifest.json                # includes the sha256 pins of all three downloads
```

All three downloads are sha256-pinned in `make_bootstrap_package.py` and
verified on every build (cache hits included; mismatches delete the suspect
artifact and abort).

Python note: **3.12.10 is the final 3.12 release with Windows binaries** —
3.12.11+ are source-only security releases (PEP 693), so no embeddable zip
exists for them. If a later Windows-binary 3.12 ever appears, update the pin
set together (`PYTHON_VERSION` + `PYTHON_EMBEDDABLE_SHA256`).

Package size ≈ 18 MB compressed.
