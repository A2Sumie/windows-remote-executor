# Windows Remote Executor V3

V3 is the only supported remote-control protocol for current Windows Remote Executor deployments.

## Stability Boundary

V3 keeps the remote command fixed:

```text
WindowsRemoteExecutor.Native.exe rpc-stdio
```

The client sends one UTF-8 JSON request line on stdin. The native executor writes one UTF-8 JSON response line on stdout. User payload does not travel in local argv, remote argv, `cmd.exe`, or PowerShell command text.

## Request

```json
{
  "id": "req-001",
  "action": "process.capture",
  "timeoutSeconds": 30,
  "captureLimitBytes": 1048576,
  "accessToken": "optional plain policy token",
  "payload": {
    "file": "whoami.exe",
    "args": []
  }
}
```

Fields:

- `id`: caller-provided correlation id.
- `action`: one supported action name.
- `timeoutSeconds`: request timeout hint. The Python transport uses it as an SSH timeout plus margin; not every native action forcibly terminates remote work yet.
- `captureLimitBytes`: capture-size hint. `file.readText` enforces `payload.maxBytes`; broad stdout/stderr truncation is deferred.
- `accessToken`: optional plain token checked against `access-policy.json`.
- `payload`: action-specific object.

## Response

```json
{
  "id": "req-001",
  "ok": true,
  "exitCode": 0,
  "errorClass": "",
  "stdoutText": "...",
  "stderrText": "...",
  "stdoutEncoding": "utf-8",
  "stderrEncoding": "utf-8",
  "stdoutBase64": "...",
  "stderrBase64": "...",
  "stdoutBytes": 3,
  "stderrBytes": 0,
  "startedAt": "2026-06-29T00:00:00.0000000+00:00",
  "endedAt": "2026-06-29T00:00:00.0100000+00:00",
  "durationMs": 10,
  "data": {},
  "evidence": ["process.capture", "rpc-stdio"]
}
```

`ok` is false for transport-level validation failures and for captured processes that return a non-zero exit code. `errorClass` is intended for routing retries: `protocol`, `auth`, `unsupported`, `path-shape`, `request`, `remote-process`, `not-found`, or `remote-exception`.

## Actions

`host.capabilities` returns the authoritative action list. Current V3 actions are:

- `host.capabilities`
- `host.probe`
- `host.guard`
- `host.repair`
- `host.tasks`
- `host.policy`
- `process.run`
- `process.capture`
- `process.spawn`
- `script.run`
- `script.capture`
- `python.run`
- `wsl.run`
- `wsl.capture`
- `wsl.script`
- `wsl.script.capture`
- `wsl.resident`
- `file.writeText`
- `file.readText`
- `file.mkdir`
- `file.deleteTree`
- `file.copy`
- `everything.search`

### `host.capabilities`

Payload: `{}`

Returns protocol metadata in `data`:

```json
{
  "protocol": "wre-rpc-stdio",
  "version": 3,
  "actions": ["host.capabilities", "process.capture"]
}
```

### `host.probe`

Payload: `{}`

Runs the native probe collector. `data` contains the probe object and `stdoutText` contains the same object as JSON plus a trailing newline.

### `host.guard`

Payload:

```json
{
  "expectedListenAddress": "100.64.1.2",
  "logPath": "C:/CodexRemote/logs/sshd-guard.log",
  "noDisable": true
}
```

Evaluates the `sshd` exposure guard. Use `noDisable: true` for validation-only matrix runs. Without `noDisable`, unsafe exposure can disable `sshd` as designed.

### `host.repair`

Payload:

```json
{
  "expectedListenAddress": "100.64.1.2",
  "codexRoot": "C:/CodexRemote",
  "logPath": "C:/CodexRemote/logs/sshd-repair.log",
  "forceRewrite": false
}
```

Repairs managed `sshd` config, host keys, scoped firewall state, service startup, and scheduled recovery tasks. This mutates host state and should be invoked intentionally.

### `host.tasks`

Payload:

```json
{
  "taskNames": ["CodexRemote Sshd Repair Watch"],
  "prefix": "CodexRemote"
}
```

Returns scheduled-task state as structured JSON without caller-authored PowerShell quoting.

### `host.policy`

Payload:

```json
{
  "exposureMode": "private-only",
  "commandMode": "standard",
  "expectedListenAddress": "100.64.1.2",
  "label": "PRIVATE-ONLY TOKEN-REQUIRED",
  "token": "plain-token"
}
```

Writes `access-policy.json` next to the native executable. `public-with-token` requires `token`. This mutates host policy and should not be part of the default safe remote matrix.

### `process.run` / `process.capture`

Payload:

```json
{
  "file": "whoami.exe",
  "cwd": "C:/CodexRemote/inbox",
  "args": ["/all"]
}
```

Runs a native Windows process through `ProcessStartInfo.ArgumentList`; no shell is used for the child process unless the requested executable is itself a shell. The Python client preserves the raw PowerShell guard: direct `powershell.exe` / `pwsh` through argv routes is blocked by default and should use `script.run` / `script.capture` unless an explicit escape hatch is provided.

`process.run` is capture-backed in V3. The CLI prints returned stdout/stderr to emulate passthrough while keeping `rpc-stdio` stdout as exactly one JSON response.

### `process.spawn`

Payload:

```json
{
  "file": "cmd.exe",
  "cwd": "C:/CodexRemote/inbox",
  "stdout": "C:/CodexRemote/logs/app.out.log",
  "stderr": "C:/CodexRemote/logs/app.err.log",
  "args": ["/d", "/s", "/c", "echo ok"]
}
```

Starts a detached Windows process using the native spawn implementation. The response is a launch receipt; callers should verify the expected process, file, port, or log separately.

### `script.run` / `script.capture`

Payload:

```json
{
  "kind": "powershell",
  "script": "$PSVersionTable.PSVersion.ToString()",
  "cwd": "C:/CodexRemote/inbox",
  "exe": "powershell.exe"
}
```

`kind` may be `powershell`/`ps` or `cmd`/`batch`. The native executor writes the script body to a temporary UTF-8 file and runs PowerShell with `-File` or `cmd.exe /d /q /c <temp-file>`. The temporary file is deleted best-effort after capture.

`script.run` is capture-backed in V3. The CLI prints returned stdout/stderr to emulate passthrough.

### `python.run`

Payload:

```json
{
  "scriptPath": "C:/CodexRemote/inbox/task.py",
  "cwd": "C:/CodexRemote/inbox",
  "python": "C:/Python312/python.exe",
  "condaEnv": null,
  "condaPrefix": null,
  "args": ["--input", "data.json"]
}
```

Runs a Windows Python script with UTF-8 environment hints. The native side can use an explicit Python executable, conda env/prefix, or a detected Python interpreter.

### `wsl.run` / `wsl.capture`

Payload:

```json
{
  "file": "/usr/bin/uname",
  "cwd": "/tmp",
  "distribution": "Ubuntu",
  "user": "sumie",
  "args": ["-a"]
}
```

Runs a Linux program through `wsl.exe --exec` with structured distro/user/cwd arguments.

### `wsl.script` / `wsl.script.capture`

Payload:

```json
{
  "script": "set -eu\nprintf '%s\\n' \"$1\"\n",
  "cwd": "/tmp",
  "distribution": "Ubuntu",
  "user": "sumie",
  "shell": "/bin/bash",
  "args": ["hello"]
}
```

Writes the script body to a temporary Windows file, translates it into WSL path form, and runs it through the requested Linux shell. The script body stays out of SSH argv and avoids `bash -lc` string composition.

### `wsl.resident`

Payload:

```json
{
  "script": "python3 -m http.server 8023",
  "launchPath": "/tmp/wre-service.sh",
  "cwd": "/home/sumie/app",
  "distribution": "Ubuntu",
  "user": "sumie",
  "shell": "/bin/bash",
  "pidFile": "/tmp/wre-service.pid",
  "logFile": "/tmp/wre-service.log",
  "port": 8023,
  "healthUrl": "http://127.0.0.1:8023/",
  "readyTimeoutSeconds": 20,
  "settleDelaySeconds": 2,
  "pollIntervalMilliseconds": 500,
  "diagnosticLines": 20,
  "args": []
}
```

Stages and launches a durable WSL service, then returns readiness diagnostics such as PID, listener state, health result, and recent logs.

### `file.writeText`

Payload:

```json
{
  "path": "C:/CodexRemote/inbox/hello.txt",
  "text": "hello\n"
}
```

Writes UTF-8 without BOM, creates the parent directory if needed, and returns a file proof in `data`: path, byte length, SHA-256, and last write time UTC.

### `file.readText`

Payload:

```json
{
  "path": "C:/CodexRemote/inbox/hello.txt",
  "maxBytes": 1048576
}
```

Reads the file bytes, decodes with the existing output decoder, returns text and base64 bytes, and returns the same file proof in `data`. If `maxBytes` is set and the file is larger, the request fails before reading the file.

### `file.mkdir`

Payload:

```json
{
  "path": "C:/CodexRemote/inbox/new dir"
}
```

Creates the directory tree if needed.

### `file.deleteTree`

Payload:

```json
{
  "path": "C:/CodexRemote/inbox/case-root"
}
```

Deletes a file or directory tree if it exists. Use intentionally; this is the cleanup primitive for controlled test roots.

### `file.copy`

Payload:

```json
{
  "source": "C:/CodexRemote/inbox/a.txt",
  "destination": "C:/CodexRemote/inbox/b.txt"
}
```

Copies a file, creates the destination parent directory if needed, overwrites any existing destination, and returns a destination proof.

### `everything.search`

Payload:

```json
{
  "query": "*.sln",
  "max": 20
}
```

Runs an Everything SDK search. This requires the Everything service and SDK DLL to be present on the target.

## Python Client

The client module is `windows-remote-executor/lib/wre_v3_client.py`. It loads the same target model as `win_remote_cli.py`, resolves the current native executor, checks help output for `rpc-stdio`, then sends the JSON request on SSH stdin.

Typical imported use:

```python
import win_remote_cli as cli
import wre_v3_client as v3

target = cli.load_target("X570")
call = v3.process_capture(target, "whoami.exe")
print(call.response["stdoutText"])
```

MCP calls this module directly rather than running `win-remote` as a subprocess.

## Deployment Rule

1. Build and publish the native executor as a GitHub release asset.
2. Deploy that asset with `win-remote update-tools <target> --native-zip <asset.zip>`.
3. Run `windows-remote-executor/scripts/verify-v3-remote-cases.sh <target>`.
4. Use MCP or `win-remote` normally; both use V3.

For a new desktop-only Windows machine, create a manual administrator bootstrap package with `scripts/make-bootstrap-package.sh`. Prefer the self-contained `scd-win-x64` release asset for a brand-new host so the native executor does not require a separate .NET 8 runtime install; the framework-dependent `fdd-win-x64` asset is also accepted when .NET 8 is already present.
