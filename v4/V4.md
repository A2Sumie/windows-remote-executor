# WRE v4 — pure-Python Windows Remote Executor protocol

V4 replaces the C# native executor with a Python embeddable interpreter launched
directly over SSH. **PowerShell, cmd.exe argv composition, and arbitrary
process.run / spawn / exec actions are gone.** Only one Windows process
launching primitive remains: scheduled-task lifecycle via TaskScheduler COM.

## Stability boundary

Remote command fixed by sshd ForceCommand or by controller-provided SSH command:

```text
C:/CodexRemote/wre/python/python.exe -I -X utf8 C:/CodexRemote/wre/rpc.py rpc-stdio
```

- stdin: one UTF-8 JSON request line, terminated by `\n`.
- stdout: one UTF-8 JSON response line, terminated by `\n`.
- stderr: not part of the contract; debugging only.

`-I` isolates interpreter (`PYTHONPATH`, `*.pth` ignored by
default). `-X utf8` forces UTF-8 IO. Payloads never travel in argv;

ssh's `cmd /d /s /c "..."` wrapper passes only the fixed entry string.

## Request

```json
{
  "id": "req-001",
  "action": "host.probe",
  "timeoutSeconds": 30,
  "accessToken": "plain policy token",
  "payload": { "categories": ["os", "sshd"] }
}
```

## Response

```json
{
  "id": "req-001",
  "ok": true,
  "protocolVersion": 4,
  "errorClass": "",
  "stdoutText": "...",
  "stderrText": "",
  "stdoutEncoding": "utf-8",
  "stdoutBase64": null,
  "stdoutBytes": 0,
  "startedAt": "2026-07-04T22:00:00+00:00",
  "endedAt": "2026-07-04T22:00:01+00:00",
  "durationMs": 1000,
  "data": { ... },
  "evidence": ["host.probe"]
}
```

`errorClass` is one of `protocol`, `auth`, `unsupported`, `path-shape`,
`request`, `remote-process`, `not-found`, `remote-exception`.

## Actions

### Host
| Action | Payload | Notes |
|---|---|---|
| `host.capabilities` | `{}` | Calls `win32com.client` to enumerate. Read-only. |
| `host.probe` | `{ "categories": ["os","sshd","policy","tasks","python"] }` | Opt-in categories; default `["os","sshd","policy"]`. |
| `host.guard` | `{ "expectedListenAddress":"100.x", "noDisable":true, "logPath":"..." }` | Read-only when `noDisable=true`. |
| `host.repair` | `{ "forceRewrite":false }` | Rewrites `sshd_config`, restarts `sshd`, ensures scheduled tasks. Best from elevated session. |
| `host.policy` | `{ "exposureMode":"private-only", "expectedListenAddress":"100.x", "label":"PRIVATE-ONLY", "token":"plain" }` | Hashes token and writes `access-policy.json`. |

### Scheduled tasks (TaskScheduler COM — no schtasks.exe)
| Action | Payload | Elevation required |
|---|---|---|
| `host.tasks.list` | `{ "prefix":"CodexRemote", "taskNames":["..."] }` | Read-only. Works non-elevated. |
| `host.tasks.detail` | `{ "name":"..." }` | Read-only. |
| `host.task.create` | `{ "name":"...", "exe":"C:/...", "args":["/c","..."], "cwd":"...", "trigger":"manual\|logon\|startup\|boot\|interval", "delay_iso":"PT30S", "interval_minutes":10, "run_as_user":"SYSTEM\|\|DOMAIN\\USER", "run_level":0\|1, "enabled":true }` | **YES.** RegisterTaskDefinition returns `0x8007052E` (LOGON_FAILURE) from a non-elevated SSH session even with S4U. Run once at deploy-wre elevated. |
| `host.task.update` | Same shape as create. | **YES.** |
| `host.task.run` | `{ "name":"..." }` | No — calling `Run()` on an existing task is an action permitted to admin-token holders without elevation. Verified. |
| `host.task.delete` | `{ "name":"..." }` | **YES** (only SYSTEM/store owned). |

### Files (stdlib pathlib / shutil)
| Action | Payload |
|---|---|
| `file.writeText` | `{ "path":"C:/...", "text":"..." }` |
| `file.readText` | `{ "path":"C:/...", "maxBytes":1048576 }` |
| `file.mkdir` | `{ "path":"C:/..." }` |
| `file.deleteTree` | `{ "path":"C:/..." }` |
| `file.copy` | `{ "source":"C:/...", "destination":"C:/..." }` |
| `file.putBinary` | `{ "path":"C:/...", "base64":"..." }` — small files only (≤ 4 MB). Use SFTP for big. |
| `file.list` | `{ "path":"C:/...", "pattern":"*.ps1", "recursive":false, "maxEntries":500 }` — bounded directory listing. |
| `file.search` | `{ "root":"C:/...", "nameGlob":"*.rs", "contentRegex":"...", "maxMatches":100, "maxFileBytes":1048576 }` — walk by name glob and/or first-match-per-file content regex. |

## Access policy

Located next to `rpc.py` at `C:/CodexRemote/wre/access-policy.json`. Same
shape as v3 except `commandMode` is locked to `"v4"`; the old `"standard"`
and `"argv-only"` values are ignored. `accessTokenSha256` enforces the
optional bearer token on all listed actions.

## Deployment

Two-stage:

1. **Light deploy** (this script, no elevation required):
   ```
   python3 -m v4.scripts.deploy_sftp <target>
   ```
   SFTP-uploads the entire `wre/` tree (embeddable Python + v4 source) to
   `C:/CodexRemote/wre/` and writes `access-policy.json` from the existing
   v3 token hash. Verify immediately:
   ```
   python3 -m v4.scripts.verify_v4_remote <target>
   ```

2. **One-time elevated deploy** (operator on the Windows host runs):
   ```
   C:\CodexRemote\wre\python\pythonw.exe C:\CodexRemote\wre\scripts\deploy-wre.py --target-name <name> --expected-listen <tailscale-ip> --access-token <plain>
   ```
   Re-creates the sshd self-repair scheduled tasks via TaskScheduler COM and
   pre-registers any app-specific tasks (e.g. StreamServ). Required only when
   you want the new v4-managed guard path or to switch v3 → v4 self-heal.

## StreamServ launch flow under v4

Pre-register ONCE during elevated deploy-wre:
```
host.task.create {
  "name": "CodexRemote StreamServ Start",
  "exe": "D:/StreamServ/start_streamserv.bat",
  "trigger": "manual",  // or "logon" if autopilot-style autostart desired
  "run_as_user": "SYSTEM",  // or "DESKTOP-X570\\sumie"
  "run_level": 1
}
```

Remotely trigger runtime:
```
host.task.run { "name": "CodexRemote StreamServ Start" }
```

Read logs:
```
file.readText { "path": "D:/StreamServ/logs/latest.log" }
```

No `process.run` / `process.spawn` / argv-from-controller anywhere.

## What was removed (vs v3)

- `process.run`, `process.capture`, `process.spawn` — replaced by TaskScheduler
  COM for resident launches.
- `script.run`, `script.capture` (PowerShell/cmd script bodies) — gone.
- `python.run` — gone. (Host Python is fixed to the embeddable interpreter; if
  a different Python is required for an app, register a scheduled task.)
- `wsl.*` actions — moved to a separate WSL control subsystem.
- `everything.search` — removed. Use `file.list` / `file.search` (stdlib walk,
  bounded) for name/content search; shell out via a scheduled elevated task if
  mass indexed search is genuinely required.
- `--allow-powershell`, `WIN_REMOTE_ALLOW_RAW_POWERSHELL` — gone.
- `argv-only` policy mode — gone; no `process.run`/`spawn` to gate anymore.
