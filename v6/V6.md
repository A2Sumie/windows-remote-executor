# WRE v6 — agent-first Windows remote executor bridge

- Date: 2026-08-18 (rebrand flip: 2026-08-19 — see "Rebrand note" below;
  log-hardening pass: 2026-08-25 — see "Hardening note" below)
- Status: implemented; **deployed at the default `C:/WRE/wre` on both X570
  and nuc-8-sumie (2026-08-25 cutover)** — the plain controller invocation
  (no `WRE_ENTRY`) is the daily route. The old sidecar `C:/CodexRemote/wre6`
  is unreferenced and pending deletion at the 2026-08-27 cleanup.
- Design: `.agent/reports/2026-08-18-wre-v6-design.md` (wins on conflict)
- Upstream: v4 audit + v5 fix tree (`v5/V5.md`)

## Hardening note (2026-08-25, from operational logs + code audit)

Fix list (`scratch/wre-v6/hardening-issues.md` H1–H20):

- **H3** orphan-reap race: a freshly-started job (supervisor still booting,
  no pids on disk yet) could be reaped as "orphan". Reaping now requires
  positive evidence — recorded dead pids, or a meta older than 90 s
  (`REAP_GRACE_SECONDS`) with no pids — re-checked under the per-job lock.
- **H1** `process.run` timeout kill is now VERIFIED: `_terminate_verified`
  retries the tree-kill and polls the pid; the result carries
  `killVerified` (false = the timed-out child survived — surface it).
- **H12** audit log rotation: `rpc-audit.log` rotates at 20 MB →
  `rpc-audit.log.1` (one generation kept). Previously unbounded since v4.
- **H14** durable job history: every job exit appends one summary line
  (jobId/exe/argsSha256/exitCode/duration/killed/timedOut + last 2 KB log
  tail) to `<WRE_ROOT>/logs/jobs-history.log`. Job logs themselves expire
  with the 24 h retention; this file is the permanent on-host record.
- **H5/H6** `file.search`/`file.list(recursive)` gain scan caps
  (`maxFiles` default 2000 / `maxScan` dirs default 20000) so a no-match
  pattern can no longer walk an entire drive; `filesExamined`/`dirsScanned`
  + `truncated` report what happened.
- **H9** controller one-shot `call()` now always has a transport deadline
  (default 600 s) even when the caller passes no timeout.
- **H20** cosmetic duplicate comment removed (files.py).

v6 keeps the v5 security rails (fail-closed token, protected-path guardrail,
audit log, sha256-pinned supply chain, no PowerShell anywhere) and rebuilds
the action surface for its actual user — an LLM agent: **one call = one
complete mental unit** (run → exit code + output; write; read; query).

## Wire protocol

Unchanged shape: stdin = one UTF-8 JSON request line, stdout = one UTF-8 JSON
response line. Payloads never travel in argv.

**Loop mode (new)**: `rpc.py rpc-stdio` now reads lines until EOF, answering
each. The controller `Session` holds ONE ssh connection for many calls, so
Python/COM startup (~600 ms cold) is paid once per session, not per call.
One-shot CLI usage is the degenerate case: write one line, close stdin, the
process exits after answering. Concurrency: serial within one connection;
async work goes through the job model (`process.start`), not threads.

Fixed remote command (controller builds it from the entry root):

```
cmd.exe /d /s /c "<entry>/python/python.exe -I -X utf8 <entry>/rpc.py rpc-stdio"
```

`<entry>` = `$WRE_ENTRY` or `--entry`, default `C:/WRE/wre`. Sidecar
deploys use e.g. `C:/WRE/wre6`. (Legacy fleet tree: `C:/CodexRemote/wre` —
reachable as ever via `WRE_ENTRY`/`--entry`.)

## Naming parameterization (WRE_ROOT / TASK_PREFIX)

All on-host paths and the scheduled-task name prefix funnel through two
constants in `v6/native/version.py`:

| Constant | Default | Env override | Used for |
|---|---|---|---|
| `WRE_ROOT` | `C:/WRE` | `WRE_ROOT` | jobs/, logs/, inbox/, protected prefixes |
| `TASK_PREFIX` | `WRE` | `WRE_TASK_PREFIX` | managed task names, tasks.list/clean default prefix |

The running rpc.py's own tree (`WRE_TREE`, derived from `__file__`) is always
protected independently — a sidecar at `wre6/` protects itself while two
hardcoded prefixes protect the fixed trees: `C:/WRE/wre` (the new default)
and `C:/CodexRemote/wre` (LEGACY, the live v4/v5 fleet tree — kept
permanently, see Rebrand note).
Controller-side overrides: `WRE_ENTRY` env or `--entry` flag; deploy script:
`--root` / `--entry-root`. The CodexRemote → WRE flip landed on 2026-08-19
as a defaults+docs change ONLY — nothing was deployed or moved on X570
(234 live tasks still reference `C:\CodexRemote\wre\python\python.exe`).

## Action surface (32 actions)

| Family | Actions | Identity |
|---|---|---|
| host | capabilities / probe / guard / repair / policy / **info** | ssh-user |
| system | **help** | ssh-user |
| tasks | tasks.list / tasks.detail / tasks.apply / **tasks.clean** / task.create(+deleteAfterRun) / task.update / task.run / task.delete | SYSTEM lane |
| file | writeText / readText(+offset/tail) / mkdir / deleteTree / copy / putBinary(≤32 MB, chunked) / list / search | ssh-user + guardrail |
| process | **run / start / wait / status / kill** | ssh-user |
| wsl | **run / list / wslpath / status** | ssh-user |

Identity model (design §7): `process.*`/`wsl.*`/`file.*` run as the SSH logon
user (non-elevated). `host.task.*` is the SYSTEM lane. There is deliberately
NO `runAs:"system"` on process.* — privilege transitions must go through
host.task.* and leave an audit trail. token == SYSTEM remains the documented
trust model.

### process.run — synchronous

```json
{"action":"process.run","payload":{
  "exe":"C:/WRE/wre/python/python.exe",
  "args":["-X","utf8","C:/work/job.py","--ep","11"],
  "cwd":"C:/work","stdinText":"...","env":{"FOO":"1"},
  "timeoutMs":600000,"captureKB":256}}
```

→ `{"exitCode":0,"stdout":"...","stderr":"...","durationMs":812,"timedOut":false,"stdoutTruncated":false,"pid":1234}`

Rules: `args` MUST be an array (shell strings rejected); `exe` MUST be an
absolute path (no PATH search — anti PATH-hijack); the timeout is enforced
server-side (kill on expiry, `timedOut:true`). `cmd /c` escape hatch:
`exe:"C:/Windows/System32/cmd.exe", args:["/d","/c","..."]` — cmd metachars
are then your problem (documented). **cmd /c quoting trap (observed on
X570)**: keep the command as separate argv words (`["/d","/c","echo","hi","&","dir"]`).
A single `"echo hi & dir"` string is quoted by list2cmdline, and cmd's
first-and-last-quote stripping rule then mangles it into "The syntax of the
command is incorrect". (v6 also normalizes the exe to backslashes because cmd
re-parses its own command line with `/` as the switch prefix.)

### process.start / wait / status / kill — async job model

```
process.start  same params → {"jobId":"j-<hex>","outputPath":"<WRE_ROOT>/jobs/j-<hex>.log"}
process.wait   {"jobId","timeoutMs","tailKB"} → exitCode + logTail (+stillRunning,+killed)
process.status {"jobId"} → state/durationMs/exitCode/outputSizeBytes/killed
process.kill   {"jobId","force":false} → terminate; force kills the tree
```

- Output ring-buffers into `<WRE_ROOT>/jobs/<id>.log` (tail kept, captureKB
  bound). Read it live with `file.readText {"path":..., "tail":4000}`.
- **Supervisor model (v6 final)**: `process.start` spawns a DETACHED per-job
  monitor (`rpc.py job-run --spec <file>`) that owns the child's pipes, the
  log, timeout enforcement, and the final metadata write — jobs therefore
  survive the answering rpc process exiting (one-shot CLI included). On
  Windows the supervisor is spawned with `CREATE_BREAKAWAY_FROM_JOB`:
  sshd-win32 kills the session's Job Object tree at close, and without
  breakaway the supervisor would die with the session (verified on X570).
  kill: targets the recorded child pid; `force` = taskkill /T /F (tree). A
  kill is recorded as `killed:true` + `killedAt` in the job metadata and
  surfaced by status/wait (`state:"killed"`), distinguishing killed jobs
  from plain exits.
- Metadata `<id>.json` lets a restarted rpc reap orphans (`state:exited`,
  `note:"reaped..."`). Retention: 24 h default.
- exe+args (full text + sha256) and every job lifecycle event land in
  `<WRE_ROOT>/logs/rpc-audit.log`.

### wsl.* — thin layer over the process primitive (zero pwsh)

`wsl.run`: `argv` → `wsl.exe [-d distro] [-u user] [--cd winCwd] --exec
<argv...>` (preferred, no shell); `shell` → `--exec bash -lc "<string>"`
(one mechanical layer). `WSL_UTF8=1` is always injected; default timeout 60 s
(idle VM spin-up). `wsl.list` parses `wsl.exe -l -v`; `wsl.wslpath`
translates paths (`to:"u"|"w"`) via `--exec` (no shell, so Windows
backslash paths survive verbatim); `wsl.status` checks availability and warms
the VM. Files interoperate via `//wsl.localhost/<distro>/...` UNC paths in
file.* (writes included: the 9P share rejects atomic rename, so writeText/
putBinary fall back to a direct write there). WSL distros are per-user: wsl.*
only exists in the SSH-user context, never in the SYSTEM lane.

**Distro lifecycle caveat (measured on X570, 2026-08):** every wsl.exe
invocation cold-boots a fresh distro session, and when that wsl.exe exits
WSL kills ALL user processes it launched — setsid/nohup children and tmux
servers included (pids restart from low numbers on the next call; a June-era
`launcher.sh --detach` pattern silently leaves a 0-byte log and a dead
service). The ONE supported pattern for a long-lived WSL service is a single
long-running `process.start` job — its detached supervisor pins the wsl.exe
session open for the job's whole lifetime:

```
process.start {"exe":"C:/Windows/System32/wsl.exe",
               "args":["-d","Ubuntu-22.04","--exec","bash","-lc","exec your-server --port 18081"]}
```

**Shell-composite exit codes:** a job's `exitCode` is faithfully the spawned
process's own status, but `bash -lc "a; b"` reports only the LAST command —
an inner build failure is masked when the composite ends in `echo` (BUG-B).
Use `set -e` or capture+re-exit (`cmd; rc=$?; echo EXIT=$rc; exit $rc`).
Jobs spawned through a shell wrapper carry `meta.exitCodeNote` stating this.

### file.* deltas

- `readText`: `offset` / `tail` (bytes, mutually exclusive; `nextOffset`
  returned for follow-reading). `base64` and `proof` are now opt-in
  (`includeBase64`/`includeProof`); proof defaults off for partial reads.
- `putBinary`: 32 MB decoded cap + `{chunkIndex,totalChunks}` resumable
  chunks (staging `<path>.wre-part`, atomic rename on the last chunk).
  Bigger → SFTP (`v6.controller.sftp` unchanged).

### host/tasks deltas

- `host.info {}` — whoami/protocolVersion/build/policy label+status/uptime/
  wreRoot/taskPrefix. Cheap enough to run before every work session.
- `system.help {"action":...}` — per-action summary + identity + example +
  JSON Schema (also all embedded in `host.capabilities` → `schemas`).
- `tasks.list` — summary fields by default (name/enabled/state/lastRunTime/
  lastTaskResult/nextRunTime); `verbose:true` adds actions/principal;
  `limit`/`olderThanDays`/`prefix` filters; `truncated` flag.
- `tasks.clean {"prefix","olderThanDays":30,"dryRun":true}` — bulk cleanup;
  dryRun defaults TRUE, infra tasks (repair trio / WRE Apply / StreamServ)
  are keep-listed, never-run tasks need `includeNeverRun:true`.
- `task.create` — `deleteAfterRun:true` self-deletes at `expiresAt`
  (default +24 h) via a DISABLED boundary trigger + `DeleteExpiredTaskAfter`;
  the trigger never fires on its own, `host.task.run` still works.

## Responses and errors

- `data` is the single source of truth. `stdoutText`/`stderrText` travel only
  with payload `"includeStdoutText": true`. (The controller's
  `call.stdout_text` falls back to `data.stdout`/`data.text`.)
- Errors: `ok:false` + `errorClass` ∈ {protocol, auth, unsupported, request,
  not-found, remote-exception} + one-line `message`. Tracebacks are opt-in
  (`"includeTraceback": true` → `traceback` field). Unknown actions get a
  `didYouMean` (edit-distance suggestion).
- `timeoutMs` (ms) everywhere; `timeoutSeconds` still accepted. Transport
  deadline = timeoutMs + 30 s margin (controller side).

## Security model (v5 rails kept, §10 additions)

Fail-closed token (missing/corrupt/null-token policy denies all but
host.capabilities), protected prefixes (`C:/WRE/wre` hardcoded + legacy
`C:/CodexRemote/wre` hardcoded + running tree dynamically +
`C:/ProgramData/ssh` + `C:/Windows` +
`<WRE_ROOT>/jobs/*.json` metadata; `allowProtected:true` override — a
fat-finger guardrail, not a boundary), rpc-audit.log, conditional sshd
restart in repair, ForceCommand opt-in, sha256-pinned supply chain (Python
3.12.10 embeddable + pywin32 308 + comtypes 1.4.8 — same pins as v5,
cache-reused and re-verified). process.* exe+args hashed AND logged in full.
Job output is ring-buffered (no disk blowup). No PATH search for exe.

Explicitly rejected (design §10.3): a resident daemon. sshd remains the only
door.

## Controller

```bash
# one-shot (one ssh per call)
python3 -m v6.controller.shell X570 process.run '{"exe":"C:/Windows/System32/cmd.exe","args":["/d","/c","echo hi"]}'
# session mode (ONE ssh for every call in the invocation) / REPL
python3 -m v6.controller.shell X570 --repl
python3 -m v6.controller.shell X570 --session host.tasks.list '{"limit":20}'
# sidecar entry
WRE_ENTRY=C:/WRE/wre6 python3 -m v6.controller.shell X570 --info
```

`Session` (v6.controller.client) auto-reconnects exactly once on transport
failure and applies a read deadline (timeoutMs + 30 s). Against a v4/v5 peer,
v6-only actions fail with an upgrade hint instead of a bare "unsupported".
